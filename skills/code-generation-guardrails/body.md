# 代码生成约束

生成简单、可维护、符合项目风格的代码。

## 适用场景

- 代码生成约束
- 适用场景
- 编写新代码
- 修改已有代码
- 实现功能
- 修复 bug
- 重构任务

## 核心原则

- 优先遵循项目已有风格，而不是抽象最佳实践
- 优先清晰表达，而不是紧凑写法
- 选择“最小正确实现”
- 不改变非必要行为
- 不扩大任务范围

## 编码前

明确：

- 目标：要做什么、不做什么
- 约束：项目规范、API、边界
- 范围：最小改动方案

如果不明确，选择最简单合理方案。

## 生成规则

### 一致性
- 遵循已有命名、结构、模式
- 不随意引入新范式

### 简洁性
- 避免深层嵌套
- 避免炫技写法
- 保持流程直观
- 必要时使用中间变量提升可读性

### 抽象控制
- 不做过早抽象
- 避免一次性 helper
- 不为未来做泛化设计

### 改动范围
- 尽量少文件、少改动
- 不修改无关代码
- 不把重构混入功能实现

### 类型与接口
- 接口清晰稳定
- 合理使用显式类型
- 避免模糊类型

### 可测试性
- 保持逻辑可验证
- 尽量隔离副作用

### 安全与质量
检查：
- 空值/越界等运行时问题
- 安全风险（注入/XSS等）
- 性能问题（重复计算/N+1）
- 接口兼容性

## 决策规则

多个方案时：

1. 优先匹配现有代码风格
2. 选择更简单的方案
3. 选择更清晰的结构
4. 选择更易测试的方案

## 生成前检查

- 是否最小实现？
- 是否引入不必要抽象？
- 是否符合项目风格？
- 是否容易理解？

## 生成后检查

- 功能正确且无额外行为变化
- 复杂度合理
- 命名清晰
- 无明显风险

## 反模式

- 过度设计
- 预期未来扩展
- 一次性抽象
- 隐式副作用
- 复杂一行代码
- 嵌套三元表达式
- 无关重构
